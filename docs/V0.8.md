# SKYNET V0.8 — Trust & Resilience

V0.8 converts the V0.7 adaptive agent into a more credible always-on local product by adding operational supervision, explicit global control, failure regression, validation evidence and state backup.

## Runtime supervision

```text
Windows startup (opt-in)
        ↓
SKYNET Supervisor
        ↓
Autonomy Worker
        ↓
independent heartbeat thread
        ↓
healthy? ── yes ──> continue
   │
   no
   ↓
terminate worker
   ↓
record crash
   ↓
restart
   ↓
crash-loop threshold?
   ├─ no  -> continue
   └─ yes -> engage global kill-switch
```

The supervisor is a separate process and does not share the worker's LLM/tool loop. It cannot grant additional permissions.

## Global kill-switch

The stop flag is stored in local runtime state and checked by `GovernedToolBus` before mandate evaluation or tool execution.

```text
LLM proposes action
      ↓
GLOBAL KILL SWITCH
      ├─ engaged -> deny + receipt
      └─ clear
           ↓
       Mandate
           ↓
       Policy Engine
           ↓
       PermissionGate
           ↓
       execution
```

The worker also exits when the switch is engaged. Desktop autonomy does not launch new due routines while stopped.

## Failure-derived regression

V0.8 mines failed trajectories into side-effect-free regression cases. It does **not** replay the original task with tools. Instead it asks the candidate/current model to analyze the historical failure and produce a recovery plan without falsely claiming success.

This catches a useful class of regressions while keeping regression testing non-destructive.

## Signed validation reports

A candidate validation report can bind:

- staged candidate SHA-256;
- immutable baseline hash;
- Red Team result;
- historical regression result;
- latest objective model scorecard;
- overall pass/fail state.

The canonical report payload is hashed and authenticated with SKYNET's local signing identity. Tampering invalidates verification.

## Backup model

V0.8 deliberately separates portability and secret preservation.

### Portable export

- ZIP + per-file SHA-256 manifest;
- excludes `identity.key`;
- can move memory, skills, policies and other non-secret runtime state to another installation;
- imported installation retains/generates its own identity.

### Windows protected full-state export

- includes identity state;
- archive bytes are protected using Windows DPAPI;
- intended for recovery under the same Windows user profile;
- not advertised as a cross-machine password-encrypted format.

SKYNET does not implement custom cryptography merely to claim portable encrypted backups.

## Startup persistence

Startup is opt-in only:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-startup.ps1
```

It creates a shortcut in the current user's Windows Startup folder targeting the venv `pythonw.exe -m skynet.supervisor_cli`.

Removal:

```powershell
powershell -ExecutionPolicy Bypass -File .\remove-startup.ps1
```

Normal `install.ps1` never installs startup persistence.

## What V0.8 still does not claim

- It does not make Windows Sandbox or WSL magically safe for all untrusted workloads.
- It does not provide cross-machine encrypted identity migration yet.
- It does not autonomously fine-tune and install models.
- It does not prove arbitrary task correctness from a language-model response.
- Historical regression replay is analysis-only, not destructive task replay.

Those limitations are deliberate.
