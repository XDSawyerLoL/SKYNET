# SKYNET V0.7 — Adaptive Lab

V0.7 connects measured evolution to machine-aware execution and real isolation backend preparation.

## Objectives

- Generate reusable candidate knowledge from repeated successful trajectories.
- Keep generated candidates untrusted until separate evaluation.
- Prefer a real Windows Sandbox security boundary when available.
- Never mislabel WSL2 or a normal subprocess as equivalent isolation.
- Route local models using measured quality and efficiency evidence.
- Preserve all mandate, permission, receipt, canary and rollback boundaries from previous milestones.

## Isolation hierarchy

```text
Windows Sandbox available?
        ├─ yes → read-only candidate mapping, network disabled, clipboard disabled
        └─ no
            ↓
WSL2 available?
        ├─ yes → compatibility/development testing only
        └─ no → static-only preparation, no execution
```

V0.7's Windows Sandbox job intentionally maps only the candidate directory read-only and a separate output directory writable. The default generated job inventories the candidate and writes evidence to the output mapping. Candidate core code is not automatically executed by this milestone.

## Candidate generation

```text
successful trajectories
        ↓
TrajectoryMiner
        ↓
repeated high-reward signature
        ↓
local LLM proposal
        ↓
Markdown skill candidate
        ↓
CandidateSandbox (SHA-256 manifest)
        ↓
lab / validation gates
```

Candidate generation is not skill promotion. The generated artifact has no authority and cannot change the core by itself.

## Adaptive routing evidence

`ModelRouter` can use:

- latest deterministic benchmark mean score;
- benchmark pass rate;
- recorded safety failures;
- task class/specialist fit;
- measured preferred or canary deployment state;
- recent latency for that model/task class;
- estimated GPU energy from sampled power and elapsed time;
- observed GPU memory pressure;
- observed RAM delta versus currently available RAM.

Missing hardware telemetry produces no penalty or invented substitute value.

## Local telemetry

The model telemetry database stays under `.skynet/model-telemetry.db` and stores only operational metrics:

```text
model
task_class
latency_s
energy_wh (when measurable)
gpu_memory_mb (when measurable)
ram_delta_mb (when measurable)
success/failure
```

It does not contain prompts or response contents.

## Why quality still dominates

Efficiency cannot promote an unsafe model. Benchmark quality/pass-rate evidence and safety failures are incorporated before resource-efficiency adjustments. Canary/promotion gates from V0.5 remain separate from everyday adaptive routing.

## Concurrency

Scorecards and model telemetry use thread-safe SQLite access so parallel tournaments and specialist swarms can record/read evidence without falling back to silent database-thread errors.

## V0.8 direction

The next milestone should focus on product-grade validation rather than raw feature count:

1. signed candidate validation reports;
2. richer domain eval packs (Windows, coding, research, planning, tool-use);
3. automatic regression replay from real failed trajectories;
4. health supervisor + crash-loop detection;
5. Windows startup/tray service packaging;
6. controlled Windows Sandbox test harness that returns structured results;
7. optional local LoRA trainer adapter, still behind baseline/red-team/benchmark/canary gates;
8. exportable/importable sovereign identity + encrypted memory backup.
