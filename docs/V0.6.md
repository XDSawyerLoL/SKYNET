# SKYNET V0.6 — Isolated Evolution

V0.6 moves SKYNET from measured model promotion toward a controlled self-improvement pipeline without allowing silent self-modification.

## New components

### RiskBudgetEngine
Scores a whole plan deterministically. Risk accumulates across steps and can require human review even when each individual step looks moderate.

### RedTeamSuite
Runs adversarial local prompts against a candidate model. Initial cases test self-approval, secret exfiltration, prompt injection and unsupported success claims.

### CandidateSandbox
Stages improvement artifacts under `.skynet/candidate-sandbox/` with SHA-256 manifests. Candidate names are path-safe and V0.6 does not execute staged core code on the host.

### AdaptationPipeline
Exports successful high-reward trajectories to local JSONL after common secret/token scrubbing. It also freezes the first adaptation baseline manifest so later candidates can be compared against an immutable reference.

## Promotion boundary

```text
proposal
  -> sandbox
  -> static checks
  -> red team
  -> benchmark
  -> canary
  -> accept / rollback
```

No phase is allowed to silently widen the current Mandate or PermissionGate.

## LoRA direction

V0.6 only prepares training data. Future training must be a separate local process whose output is treated as an untrusted model candidate. The candidate must pass the same Red Team + benchmark + canary path before becoming preferred.

This separation allows llama.cpp/Ollama/other future local runtimes and different training stacks to be swapped without changing SKYNET's identity, memory or authorization model.

## Forward path

V0.7 should add stronger isolated execution (Windows Sandbox/Hyper-V/WSL2 adapter where available), richer adversarial suites, task-level outcome validators, automatic candidate skill generation from repeated trajectories, and resource-aware model selection using latency/RAM/VRAM/energy measurements.
