# SKYNET V0.4 — Sovereign Agent Fabric

## Why this milestone exists

V0.4 turns SKYNET from a capable local agent into a governed agent fabric. The key architectural rule is that model reasoning, authorization and execution are separate systems.

```text
Intent -> Plan -> Proposed Action -> Mandate -> Policy Decision -> Permission -> Execution -> Receipt
```

The language model is never the authority that decides whether its own consequential action is allowed.

## New subsystems

### Sovereign local identity

A local identity is generated once inside `.skynet/identity.key`. V0.4 uses HMAC-SHA256 for local tamper evidence with no external crypto dependency. Public-key and hardware-backed identities are future adapters.

### Canonical Mandate

`.skynet/mandate.json` is the local source of truth for executable authority. It supports:

- allowed and blocked actions;
- allowed and blocked targets;
- per-action and daily value ceilings;
- activation and expiry windows;
- maximum risk score;
- reversible-only mode;
- optional mandatory human authorization.

### Deterministic PolicyEngine

Policy evaluation is normal Python code, not an LLM prompt. It checks identity, time window, replay nonce, action/target allowlists, value limits, risk and reversibility.

### Signed receipt chain

Every governed action receives a local receipt chained to the previous receipt and signed by the local identity. The chain is independently verifiable with `:verify-receipts`.

### External policy projections

The canonical Mandate can be projected toward:

- ERC-8196 fields;
- AP2-style constraints;
- delegated OAuth-style scopes.

These adapters do not make SKYNET dependent on any external payment, blockchain or identity system.

### Parallel bounded swarm

The swarm engine runs independent local specialists in parallel and then synthesizes their reports. Default roles are planner, analyst, critic, security and verifier. The worker count is bounded by configuration.

### Semantic memory

Semantic memory is stored locally in SQLite. If an Ollama embedding model is configured, it is used locally. Otherwise a deterministic hashed vector fallback works without new dependencies.

### Trajectory evidence

SKYNET records goals, chosen model, outcome, reward placeholder, evidence and metadata. This creates the dataset needed later for measured skill discovery, routing improvement and optional local adapters/fine-tuning.

### A2A-ready agent registry

V0.4 introduces protocol-neutral Agent Cards and delegated task envelopes. This is intentionally marked A2A-ready, not fully A2A v1 compliant yet. A future HTTP adapter can implement the official transport without changing SKYNET's internal identities or mandates.

## What SKYNET takes from the current ecosystem

- Ruflo: bounded multi-agent specialization, parallelism, trajectory learning direction.
- Hermes: reusable skill learning and persistent agent behavior.
- OpenClaw: persistent operation, tools and automation patterns.
- OpenComputer: observe-act-verify desktop loop.
- OpenJarvis: local-first routing and model efficiency mindset.
- MCP: agent-to-tool interoperability.
- A2A: agent-to-agent interoperability boundary.
- AP2 / ERC-8196: deterministic mandate and receipt separation.

SKYNET does not make any of those projects its mandatory core.

## Forward architecture — anticipated next layer

### V0.5: Trust Fabric

- full A2A v1 adapter + Agent Cards over HTTP;
- capability delegation with mandate inheritance and narrowing;
- cascade revocation for delegated agents;
- signed task envelopes and remote receipt verification;
- policy adapters for AP2/x402/OAuth-style grants;
- hardware-backed signing when available;
- stronger Windows sandbox backend for generated code;
- evaluation harness for swarms and routing.

### V0.6: Local Learning Loop

- outcome scorer and user feedback signals;
- trajectory clustering;
- automatic skill candidate extraction;
- benchmark-before/after promotion;
- local LoRA/adapters only after measurable gain;
- automatic rollback if quality or safety regresses.

### Long-term

The intended product is a sovereign personal AI operating layer whose identity, memories, mandates, skills and history survive model changes. Models become replaceable cognition engines rather than the product itself.
