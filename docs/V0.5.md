# SKYNET V0.5 — Measured Evolution

V0.5 turns the V0.4 evidence layer into a controlled evolution loop.

## Why

A sovereign agent should improve without trusting its own subjective claim that it improved. Changes must be evaluated outside the reasoning loop, compared with a known baseline, canaried, and reversible.

## Evolution boundary

```text
agent experience
      ↓
trajectory evidence
      ↓
pattern mining
      ↓
candidate change
      ↓
objective eval suite
      ↓
scorecard
      ↓
deterministic promotion rule
      ↓
explicit canary boundary
      ↓
accept / rollback
```

No component in this loop edits SKYNET core source code automatically.

## Objective evaluator

`evolution.py` defines deterministic evaluation cases containing:

- prompt;
- required terms;
- forbidden terms;
- weight;
- optional latency ceiling.

This deliberately avoids making one LLM the sole judge of another LLM. Domain-specific suites can be added locally.

Promotion currently requires:

- no candidate safety failures;
- no pass-rate regression versus baseline;
- minimum mean-score gain (default 0.05).

## Canary routing

`routing.py` accepts measured deployment state.

A canary model is assigned a bounded fraction of prompts using a SHA-256 bucket derived from the exact prompt. This gives deterministic traffic assignment: the same input is compared consistently while the candidate is under observation.

Accepted deployments receive a preference bonus in normal routing, while strong specialists (for example a coder model) can still win role-specific routing.

## Rollback

`deployment.py` keeps atomic local deployment state:

- active candidate;
- previous candidate;
- canary/active/rolled_back status;
- scorecard linkage/metadata.

Rollback never requires the candidate model to cooperate.

## Trajectory miner

`TrajectoryMiner` detects repeated high-reward successful goal signatures. It produces learning proposals only. It does not create executable code, promote skills, or fine-tune models.

The next safe step is to use proposals to generate versioned skill candidates or training examples, then evaluate them through the same benchmark/canary boundary.

## Capability leases

`delegation.py` introduces signed delegated capabilities for future A2A-style operation.

A lease binds:

```text
issuer identity
subject agent
capabilities
mandate hash
expiry
call budget
signature
revocation state
```

This is intentionally narrower than transferring the owner's identity or credentials to another agent.

## Relationship to external standards

SKYNET keeps protocol-neutral internal objects and adapts outward:

```text
Canonical Mandate ──> ERC-8196 / AP2 / OAuth / future policy adapters
Capability Lease  ──> future A2A credential/delegation adapters
MCP               ──> tools and context
Agent Registry    ──> future A2A discovery/task transport
```

External standards can change without invalidating SKYNET's local identity, policy, memory or deployment state.

## Forward roadmap

Candidate V0.6 work:

1. policy simulation / dry-run before consequential multi-step plans;
2. risk budget across an entire plan, not only individual tool calls;
3. real canary outcome telemetry linked to trajectory rewards;
4. skill candidate generation from repeated trajectories with diffable provenance;
5. isolated adapter/LoRA training pipeline with immutable baseline checkpoints;
6. adversarial red-team eval suites before promotion;
7. remote A2A transport adapter with lease verification and zero implicit trust;
8. optional OS-level sandbox for generated executables/processes;
9. resource-aware scheduling across CPU/GPU/RAM/energy constraints;
10. signed export/import of sovereign identity-adjacent state without exporting private signing material by default.
