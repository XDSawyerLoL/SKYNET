# SKYNET V0.10 — Reality Accelerator

V0.10 is the accelerated experience layer between Product Convergence and the real-PC benchmark.

It does **not** claim that synthetic time is identical to physical-world usage. Instead it compresses repeatable classes of operational stress into deterministic, high-throughput episodes so software, policy and recovery defects can be found before field testing.

## Three evidence lanes

### 1. Core soak — thousands of synthetic operational hours

`skynet-sim core` runs real SKYNET persistence/policy components against deterministic fault classes without requiring an LLM or cloud service.

Current fault classes:

- duplicate channel delivery;
- denied permission pressure;
- nonce replay;
- risk overflow;
- expired mandates;
- session handoff/fork;
- crash/reopen recovery;
- unknown-tool injection.

Each episode exercises real `MemoryStore`, `SessionStore`, `ChannelHub`, `RoutineStore`, `PermissionGate`, `PolicyEngine` and `ReceiptStore` code. Failures are written as machine-readable regression seeds.

CI runs 1,000 episodes with one synthetic operational hour reported per episode. This is called **virtual operational time**, not literal elapsed experience.

```powershell
.\.venv\Scripts\skynet-sim.exe core --episodes 10000 --workers 8 --strict
```

### 2. Model-in-the-loop synthetic arena

`skynet-sim agent` runs the real configured local Ollama model with the real SKYNET `Agent` loop, but only against an isolated synthetic tool bus with no filesystem, network, shell or desktop authority.

Scenarios include:

- normal change + mandatory verification;
- hostile prompt injection inside tool output;
- denied user approval;
- transient tool failure and recovery;
- impossible target where false success must be avoided.

```powershell
.\.venv\Scripts\skynet-sim.exe agent --episodes 100 --model qwen3:8b
```

The arena scores observable behavior such as whether the target was actually reached, whether authoritative verification occurred, whether a synthetic secret-export trap was followed and whether a blocker was reported instead of inventing success.

### 3. Shadow replay of real history

`skynet-sim shadow` inspects historical trajectories without invoking tools or causing side effects. Suspicious cases can be promoted into the existing failure-regression pipeline.

```powershell
.\.venv\Scripts\skynet-sim.exe shadow --limit 1000
.\.venv\Scripts\skynet-sim.exe promote-failures --limit 500
```

## Idempotent channels

V0.10 also hardens the channel layer for real webhook behavior. External adapters may supply a stable `dedupe_key` / event id. A retried inbound or outbound event returns the original message instead of duplicating it, including after process restart.

The local webhook bridge accepts either:

- `X-SKYNET-Event-ID` header; or
- JSON `event_id`.

Replies use a deterministic dedupe key derived from the inbound message id.

## Why this exists

Recent long-horizon agent benchmarks increasingly use automated user simulation, sandboxed execution, programmatic verification, parallel rollouts and generated tasks to scale experience collection. SKYNET follows the same general direction while keeping the accelerator local-first and tied directly to its own governance/recovery invariants.

The accelerator is intentionally layered:

```text
fast deterministic core soak
        ↓
model-in-loop synthetic arena
        ↓
shadow replay / regression mining
        ↓
real Windows benchmark
        ↓
new failures feed regression + simulation
```

## Promotion rule

Synthetic success never proves real-world readiness. It only raises the confidence floor and removes repeatable defects cheaply.

The real-PC benchmark remains mandatory before claiming production-grade Windows autonomy.
