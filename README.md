# SKYNET

**Sovereign local-first governed personal AI for Windows.**

SKYNET owns the agent core and treats models, runtimes, connectors, payment rails and external authorization systems as replaceable adapters. No paid API is required for the default setup.

Current milestone: **V0.7 — Adaptive Lab**

## What V0.7 adds

- Real backend discovery for **Windows Sandbox**, WSL2 compatibility testing and static-only fallback.
- Windows Sandbox jobs use a read-only candidate mapping with networking, clipboard and printer redirection disabled.
- Automatic **candidate skill generation from repeated successful trajectories** using a local model; generated artifacts remain staged/untrusted.
- Dependency-free local hardware profiler for CPU/RAM plus optional NVIDIA VRAM/power telemetry through `nvidia-smi`.
- Persistent per-model telemetry: latency, energy estimate, GPU memory pressure and RAM delta.
- Resource-aware model routing that can combine benchmark quality, pass rate, safety failures, latency, RAM/VRAM pressure, energy evidence, specialist fit and canary state.
- Thread-safe scorecards and telemetry for parallel tournaments/swarms.
- Desktop evolution panel now reports hardware, telemetry and selected lab backend.

V0.7 keeps all V0.6 protections: plan-level risk budgets, Red Team, candidate staging, immutable baseline, secret-scrubbed adaptation export, measured tournaments, canary/rollback, capability leases, canonical mandates, deterministic policy enforcement and signed receipts.

## Adaptive evolution loop

```text
real task
   ↓
trajectory + evidence
   ↓
repeated successful pattern
   ↓
local candidate generator
   ↓
staged candidate (untrusted)
   ↓
Adaptive Lab
   ├─ Windows Sandbox: security boundary when available
   ├─ WSL2: compatibility/development backend
   └─ static-only: never executes candidate code
   ↓
Red Team + deterministic checks
   ↓
objective benchmark
   ↓
measured resource telemetry
   ↓
canary
   ↓
accept OR rollback
```

Generated candidates never receive new permissions merely because they were generated by SKYNET.

## Resource-aware routing

The router no longer relies only on model-name heuristics. When evidence exists it can use:

```text
quality score + pass rate
+ safety record
+ task specialization
+ historical latency
+ VRAM pressure
+ RAM pressure
+ GPU energy estimate
+ measured preferred/canary state
```

No hardware metric is invented. Missing metrics stay unknown and do not become fake numbers.

## Adaptive Lab

See available backends:

```powershell
.\.venv\Scripts\skynet-evolve.exe lab-backends
```

Stage a candidate manually:

```powershell
.\.venv\Scripts\skynet-evolve.exe sandbox-stage candidate-1 skill .\proposal.md
```

Or generate a candidate from repeated successful trajectories:

```powershell
.\.venv\Scripts\skynet-evolve.exe generate-candidate
```

Prepare a lab job using the best available backend:

```powershell
.\.venv\Scripts\skynet-evolve.exe lab-prepare auto-example
```

Or explicitly choose a backend:

```powershell
.\.venv\Scripts\skynet-evolve.exe lab-prepare auto-example windows-sandbox
.\.venv\Scripts\skynet-evolve.exe lab-prepare auto-example wsl2
.\.venv\Scripts\skynet-evolve.exe lab-prepare auto-example static-only
```

Run a prepared job:

```powershell
.\.venv\Scripts\skynet-evolve.exe lab-run <job_id>
```

**Security note:** only Windows Sandbox is labelled a security boundary by SKYNET V0.7. WSL2 is deliberately labelled as a compatibility/development backend rather than being falsely presented as equivalent isolation.

## Sovereignty rules

1. Models are replaceable.
2. Memory, trajectories, policies, receipts, telemetry, scorecards and deployment state remain local by default.
3. No cloud API is required for core operation.
4. The LLM never decides whether its own consequential action is authorized.
5. Generated improvements remain untrusted candidates until independently evaluated.
6. Candidate core code is not executed directly on the host by the normal SKYNET runtime.
7. Windows Sandbox is preferred when a real local isolation boundary is available.
8. Adaptation data is scrubbed for common secret/token patterns.
9. A baseline cannot be silently replaced.
10. Promotion requires measured evidence and remains rollback-capable.
11. Resource-aware routing uses observations, not invented hardware metrics.
12. External protocols remain adapters, never SKYNET's sovereign source of truth.

Runtime data lives under `.skynet/` by default. See `docs/V0.7.md` for the milestone architecture.
